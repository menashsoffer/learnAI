# ארכיטקטורה

מסמך אחד שמסביר איפה כל דבר יושב ולמה. אם משהו כאן לא תואם לקוד — הקוד צודק, והמסמך צריך עדכון.

## מה זה הדבר הזה

אתר-מצגת שמלווה הרצאה חיה, ומריץ אותה בשלושה מצבים מאותו תוכן: מנחה, משתתפים, וצפייה
רגילה. הוא נבנה לשני יעדים — אתר מתארח, וקובץ HTML יחיד שרץ אופליין לגמרי מכונן USB.

## שכבות

הקוד מסודר בשכבות עם כיוון תלות אחד. שכבה מכירה רק את מי שמתחתיה.

```
ui/          מה שרואים — chrome, player, presenter, participant, routes
   ↓
scenes/      תוספי טיפוסי-סצנה   +   blocks/   בלוקי תוכן מוצהרים
   ↓
react/       מתאמים בין המנוע ל-React (provider + hooks)
   ↓
engine/      ליבה טהורה: ניווט, דק, טיימר, deep links
```

לצד אלה, ובלי תלות בכיוון מסוים: `theme/` (טוקנים וסגנון בסיס), `assets/` (מותג ואיורים),
`i18n/`, `persistence/`, `analytics/`.

## שלושה כללים שנאכפים אוטומטית

הם לא המלצות — ESLint נכשל עליהם.

**1. המנוע לא מכיר React.** `src/engine/**` הוא TypeScript טהור: בלי `react`, בלי DOM, בלי
`zustand` ישירות, ובלי לייבא מ-`@/react` או `@/scenes`. הסיבה מעשית: הלוגיקה של ניווט,
טיימר וקישורים נבדקת בלי לרנדר כלום, והבדיקות רצות במילישניות.

**2. תוכן הוא נתונים, לא HTML.** אין `dangerouslySetInnerHTML` בשום מקום. תוכן סצנה מורכב
מבלוקים מוצהרים (`src/blocks/types.ts`). ויזואל ייחודי הוא טיפוס סצנה חדש, לא HTML גולמי.

**3. הארטיפקט האופליין לא פונה לרשת.** אין sink אנליטיקה עם רשת ב-`src/analytics`, הדקים
מיובאים ולא נשלפים ב-fetch, וכל הנכסים מוטמעים כ-data URI. `npm run build:offline` מייצר
קובץ אחד שעובד בלי אינטרנט.

## איך מוסיפים דברים

### טיפוס סצנה חדש

תיקייה תחת `src/scenes/<type>/` עם `defineScene({ type, schema, Component, defaultData })`,
ושורה אחת ב-`src/scenes/index.ts`. הרישום זורק על טיפוס כפול, אז שגיאת העתק-הדבק נכשלת ברעש.
טיפוס לא מוכר בדק לא מפיל את המצגת — הוא נופל ל-`_fallback`.

הטיפוסים הקיימים: `hero`, `content-skill`, `workshop-instructions`.

### דק חדש

`content/decks/<id>/deck.json` + שורה ב-`content/decks/index.ts`.

### CSS

סדר השכבות הוא סדר הייבוא (`cssCodeSplit` כבוי בבנייה האופליין), והוא מוגדר במפורש
ב-`src/main.tsx`: `tokens/scale` ← `tokens/palette` ← `layout` ← `primitives`. אחרי זה כל קומפוננטה מייבאת את
הגיליון שלה.

**מחלקה שמשמשת יותר מתיקייה אחת עוברת ל-`src/theme/primitives.css`.** תיקיית פיצ׳ר לא
מחזיקה מחלקה שאחיותיה תלויות בה — זה עובד רק בזכות סדר טעינה, ונשבר בשקט ביום שהקובץ
מפסיק להיות מיובא.

## שלושת המצבים

מסלול אחד (`PlayerRoute`) מגיש את שלושתם; ההבדל הוא `mode`.

| מצב       | נתיב                        | מה מיוחד                            |
| :-------- | :-------------------------- | :---------------------------------- |
| `present` | `#/d/:deckId/present/:slug` | מגירת הנחיה, טיימר, הצצה לסצנה הבאה |
| `study`   | `#/d/:deckId/study/:slug`   | דק מסונן — רק סצנות עם `student`    |
| `plain`   | `#/d/:deckId/:slug`         | נגן נייטרלי, לשיתוף אחרי ההרצאה     |

דק המשתתפים הוא תת-קבוצה אמיתית: `participantDeck()` מסנן לסצנות שיש להן `student`, והמנוע
ממשיך לעבוד על הדק הקטן — מונה, רשת וקישורים עמוקים כולם נכונים בלי טיפול מיוחד.

## כללי תוכן

לכל סצנה ארבעה שדות תוכן, ולכל אחד קהל אחר. זה הכלל המרכזי של הדק:

| שדה               | מי רואה              | הכלל                                            |
| :---------------- | :------------------- | :---------------------------------------------- |
| `data`            | הקהל, על המסך הגדול  | מינימלי — כותרת ועוגן קצר. אף פעם לא פסקת הסבר. |
| `notes`           | המנחה בלבד           | מה לעשות: שאלות לקהל, הדגמות, תזמון             |
| `presenterScript` | המנחה בלבד           | מה להגיד                                        |
| `student`         | המשתתפים במכשיר שלהם | ההסבר המלא והפרומפטים להעתקה                    |

המסך מלווה את המרצה, לא מתחרה בו.

## יציבות קישורים

`slug` הוא API. `scripts/released-slugs.json` מחזיק את מה שכבר פורסם, ו-`npm run validate:decks`
נכשל אם slug נעלם בלי רשומה מתאימה ב-`meta.redirects`. קישור ששותף אחרי הרצאה חייב להמשיך לעבוד.

## בדיקות

בדיקות יושבות ליד הקוד שהן בודקות (`*.test.ts`). המנוע מכוסה היטב כי הוא טהור וזול לבדוק.
`npm run verify` מריץ את מה ש-CI מריץ: טיפוסים, lint, פורמט, בדיקות, וולידציית דקים.
